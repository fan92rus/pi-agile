# Amendment 4 (rev.5) — быстро и дёшево без повторной генерации

## Решение ведущего

Успешный результат rev.3 (`d036579`) уже прошёл два свежих ревью и script-мерж. Платить за повторную генерацию того же контракта каждый запуск бессмысленно: именно `work` съедал основную часть токенов в rev.4 (1,74M fresh на 11 неудачных прогонов).

Rev.5 переключает пилот с «generate every run» на **reuse-first**:

1. `seed.patch` — зафиксированный диф успешного воркера, совмещённый с переносимыми фикстурами `node -e 0` из `4d36c54`.
2. Script-фаза `seed` применяет патч к ветке `tf-pilot/8en`.
3. Script-фаза `seed-check` делает `contract-check` + `parse-check` за ноль токенов.
4. Агент `work` получает `when: "{steps.seed-check.output} != \"SEED OK\""`: вызывается только если заготовка сломана, и чинит только причины отказа.
5. Все остальные проверки остались обязательными: `contract-check`, `parse-check`, `npm test`, два свежих ревью на `opencode-go/hy4-flash-free`, три score gate, script commit/merge.

## Дополнительные меры экономии

- `onBlock: retry` убраны с `gate-contract` и `gate-parse`: повтор identical prompt не исправлял дефекты и удваивал стоимость.
- `seed-check` больше не гоняет `npm test` — его гоняет одна фаза `verify`.
- Бюджет снижен с 2M до 1,2M токенов.
- Ревьюеры сохраняют `cache.scope: cross-run` с fingerprint по git HEAD и содержимому двух файлов: повторный запуск на том же результате не вызывает LLM.
- Диагностика taskflow: `when` с некавычённым литералом (`contains SEED FAIL`) **не фильтрует** фазу; рабочая форма — `!= "SEED OK"` (проверено отдельными zero-token probe-прогонами `when-probe4..7`).

## Доработка P0/P1 (после измерения)

- **P0:** `report` и `report-stub` больше не трогают `results.md`; черновики пишутся в `reports/report-<base>.md` и `reports/stub-<timestamp>.md`. Проверено прогоном `agile-leaf-pilot-mwyfq258-571104`: хеш `results.md` не изменился. Повторный прогон `agile-leaf-pilot-mwyfy22k-c08289` завершился `completed` (`cca0772`).
- **P1:** добавлен отдельный `rework-flow.json`. Он берёт дословные `blockers` ревью через аргумент `args.blockers`, запускает целевой fix до 8 turn-ов, затем `contract/parse/npm`, два свежих ревью и те же score gates. В основной быстрый flow ветвление не вставлено: probe показал, что фазы с невыполненным `when` блокируют зависимые gate, поэтому условный rework внутри одного DAG честно не заработал. Вынесенный flow — рабочий вариант без риска для быстрого пути.

## Ограничения

- Сводка по-прежнему дописывается в `results.md` только `metrics.mjs`; черновики изолированы.
- cross-run cache ревьюеров привязан к содержимому двух файлов; при любом изменении кода ревью перевызывается, как и положено.
- Проверка «no bd» остаётся статической: у агентов нет bash, а seed.patch содержит только два целевых файла.
- `rework-flow.json` ожидает, что клон уже находится на ветке `tf-pilot/8en` с применённым seed; это ручной инструмент разбора заблокированного прогона, а не автопродолжение основного flow.
